# 写作指南

这里是一套可复用的软著写作流程与规范。你不必让AI代写——按指南自己写同样可以。若用AI，可让AI读仓库根目录的 `CLAUDE.md` 一次跑完全程，也可把单个文件交给AI作为任务说明。

| 文件 | 用途 |
|------|------|
| `01-handbook-guide.md` | 写说明书各章（引言、安装、使用、架构、数据、附录） |
| `02-source-code-guide.md` | 准备源码副本、写源程序文档、编译验收 |
| `03-application-guide.md` | 填申请表（字数限制、命名一致性） |
| `04-review-guide.md` | 与真实源码一致性核对、去AI味、版面验收 |
| `writing-style.md` | 中文写作规范（去AI味、标点空格、术语；软著、论文、推文通用） |
| `author-philosophy.md` | 写作总原则：像程序包使用手册一样写，需求导向、精简 |

用法：把对应文件的内容整段作为AI的参考说明，并在前面附上你的真实软件信息（软件名、版本、功能、源码路径、截图）。自己写时，把每个文件当作该阶段的检查清单。

另见 `softcopy-toolkit/prompts.md`：工具链自带的完整撰写约定（文档结构、LaTeX规范、登记合规要点），是这些分步指南的原始出处，保持原样未改。
