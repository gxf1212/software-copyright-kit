# 指南4：一致性核对与去AI味

## 使用方式

说明书和源程序文档写完后，按本清单做终检。可交给AI执行，也可自己逐条核对。先读真实源码和仓库里的 `guidelines/writing-style.md`。

## 终检清单

分两轮做：先一致性与真实性核对，再去AI味与排版。

### 第一轮：事实与真实性核对

1. 从开发目录抓取真实源码的函数签名、参数、模块路径、文件路径。
2. 逐章核对说明书里的API、参数、模块路径、文件名，修正不一致。
3. 对照 `materials/facts.md` 核对关键数字、定义、统计范围是否跨章节一致；数字相近但范围不同的（如全量、已测、候选）不能混用。
4. 检查“支持”“自动”“实时”“预测”“验证”“训练”等动词：区分真实计算、历史结果展示、缓存、日志回放和演示功能；有模型的软件要分清训练表现、交叉验证、独立测试和最终预测。不能验证的标注“待用户确认”，不要替用户下结论。
5. **每条写进文档的命令都实际跑一遍**：找到函数只是第一层，还要确认参数传递完整、默认值正确、入口不依赖特殊环境。
6. 核对 `source-code.tex` / `code_simplified.tex` 是否与真实源码范围一致，去掉旧代码。
7. 核对申请表、说明书封面、源码页眉三处的软件全称与版本号完全一致；界面截图名称与全称一致。
8. 删除冗余正文或重复示例，编译后确认页数。核对基线记录在各软著包自己的文档目录下，不要混进通用工具目录。

### 第二轮：去AI味与排版

按 `guidelines/writing-style.md` 逐条检查：

- **删填充词**：把词删掉后句子不损失信息，就删。删“明显”“口径”“似乎”等AI常用词。
- **清零“不是…而是…”句式**：包括“而不是”“而非”“不再”“并不能只”。改成正面陈述。
- **删防御性表述**：不写“该图由某工具生成”“这里说明一下”之类；不暴露内部校对痕迹。
- **长段拆、短段并**：一段一个要点；过短的列表合成一段；每条不少于20字。
- **中文标点**：全角标点；数字/英文与中文之间不加空格；斜杠用半角 `/`。
- **术语统一**：同一个词全文一致，专业名词首次出现写全称。
- **加粗克制**：只在关键处加粗；引用块用于punchline，不用于复述。
- **引用格式**：写“见\ref”、“见图\ref”统一按仓库规范处理。
- **表格与正文分工**：表格里不堆解释，正文不重复表格数据；三线表居中。

### 版面验收

```bash
python softcopy-toolkit/check_pdf_lines.py software_copyright/document.pdf --kind document --scope deposit
python softcopy-toolkit/check_pdf_lines.py software_copyright/source-code.pdf --kind source --scope deposit
```

- 源程序每页不少于50行，文档每页不少于30行；不足时调整排版，不要删内容凑数。
- 截图页、结束页等按规则豁免，用 `--exempt-pages` 标注。
- 表格跨页大片空白要修，不能只调小字体。
- 需要节选时用 `extract_front_back_pages.py` 取前后各30页，开头的封面和目录会自动排除，前30页从正文第1页起算。
- 节选后人工核对页码连续、源文件顺序、代码完整、封面是否已排除。

其他自动检查（辅助，警告不等于不合规）：

```bash
bash tests/smoke.sh                                  # 端到端冒烟测试
python softcopy-toolkit/check_privacy.py .           # 发布前个人信息与占位符检查
python softcopy-toolkit/freeze_version.py            # 版本冻结：commit/哈希/日期/PDF
```

编译后建议生成页面缩略图总览，人工扫一眼有没有大片空白、截图过小、代码溢出、页眉重叠。检查器只统计印刷视觉行，长代码自动折行会被算成多行，不能替代人工核对。

### 输出要求

逐条说明：哪些问题已改、哪些按用户原意保留、哪些需要用户确认。不要擅自删除用户手动加入的文字。
