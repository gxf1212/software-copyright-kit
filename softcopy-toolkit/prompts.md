## 基本要求  
你是一名专业的软件著作权撰写顾问，熟悉知识产权法律法规与软件开发流程。请根据以下要求，撰写一份正式、合规且具备法律与技术严谨度的软件著作权说明文档，并确保输出内容可以直接用于申请或备案参考。
document.tex 里面包含子文档 software-copyright/1-introduction.tex、2-installation.tex 之类的，是要写子文档的内容，可以删掉多余的子文件、改文件名什么的，要写中文！源程序文档主文档是 source-code.tex，主要是编辑 code_simplified.tex，只写 `\section`、`\subsection` 等和 `\lstinputlisting` 语句

## 工具脚本约定
- `software-copyright/softcopy-toolkit/compile.sh`：编译使用说明文档或源程序文档。通常在对应目录下执行 `bash ../softcopy-toolkit/compile.sh document.tex` 或 `bash ../softcopy-toolkit/compile.sh source-code.tex`。
- `software-copyright/softcopy-toolkit/count_lines.py`：统计源程序文档所引用代码的总行数；加上 `--remove-empty` 时会先清理代码副本中的空行，再输出文件数和总行数。
- `software-copyright/softcopy-toolkit/extract_front_back_pages.py`：从完整 PDF 中提取前若干页与后若干页，生成软著提交用节选 PDF；默认保留前30页和后30页，并自动去重重叠页。
- `software-copyright/softcopy-toolkit/prompts.md`：记录软著文档撰写、目录组织、代码节选和提取流程的提示词与使用约定，修改文档结构或新增软著目录时应优先参考。
- `software-copyright/softcopy-toolkit/serve_docs.py`：本地 Web 查看软著 PDF（`document.pdf`、`source-code.pdf`）。在 `software-copyright/` 目录下执行 `python3 softcopy-toolkit/serve_docs.py`，浏览器打开 http://localhost:8000/ 查看索引页；支持 Range 请求与目录索引，可用 `--port`、`--bind` 调整监听；跨机访问用 SSH 端口转发（`ssh -L 8000:127.0.0.1:8000 <host>`），不要直接暴露到内网。停止用 `pkill -f serve_docs.py`。
- 源程序文档在更新 `code_simplified.tex` 后，应先在对应软著包内运行其 `sync_code_listings.py`（若该包提供）同步代码副本到提交目录，再运行 `count_lines.py <software-copyright 下的代码副本目录> --remove-empty` 清理空行并统计行数，最后编译 `source-code.tex`。`--remove-empty` 会就地改写文件，只允许在路径包含 `software-copyright` 的提交副本上运行，不要指向原始开发源码。

## 文档结构  

引言  
- 软件简介：简要介绍软件的功能、用途和目标用户群体。  
- 适用对象：明确软件的目标用户或行业领域。  
- 编写目的：说明文档的目的，例如帮助用户了解软件功能、安装部署方法等。  

软件基本信息  
- 软件名称  
- 版本号  
- 开发单位/个人  
- 完成时间  
- 运行平台（操作系统、硬件环境等）  
- 编程语言及框架  
- 环境配置与安装部署  
  - 硬件需求：列出运行软件所需的最低硬件配置。  
  - 依赖库：详细说明需要安装的第三方库及其版本。  
  - 安装步骤：提供清晰的安装指南，包括命令行操作示例。  
  - 启动服务方式：描述如何启动软件及其相关服务。  

软件功能概述  
- 核心功能点：列举软件的主要功能模块及其作用。  
- 系统架构图：以文字描述或引用外部文件的方式展示系统架构。  
- 模块说明：逐一说明各功能模块的作用和技术实现。  
- 技术栈：列出软件使用的技术工具、框架和库。  

数据库或文件结构说明  
- 详细说明数据库表结构、数据存储格式，或文件存储的设计。  

API接口或使用方法  
- 请求方式：描述 API 的调用方式（如 HTTP 请求）。  
- 参数说明：列出所有可能的输入参数及其含义。  
- 返回示例：提供 API 返回值的样例数据。  

其他补充说明或附录  
- 主要第三方依赖的许可证  
- 引用项目文件清单  
- 其他需要补充的内容  

语言风格  
- 使用正式、客观的措辞，确保法律与技术并重。  
- 避免使用不确定性、口语化或含糊的表述。  
- 文字表达简洁明了，减少赘词。  

法律合规  
- 文档中不涉及机密或敏感信息的披露。如有相关内容，请以“本段已做保密处理”标识或省略。  
- 对涉及的外部库或 API，请注明来源及版权信息。  
- 文档中如有涉及第三方版权的部分，需作出相应引注或提醒。  

可读性与可操作性  
- 让读者通过文档即可快速了解软件的全部功能、技术实现概要，以及如何安装、部署与使用。  
- 提供必要的例子或脚本示例，帮助使用者快速上手。  

排版与格式  
- 使用有序/无序列表、表格、分级标题等方式让内容清晰易读。  
- 段落简洁，每段不宜过长。  
- 在结尾附上：  
  - 参考文献或相关链接：若使用第三方资料或工具，请列出来源。  
  - 更新日志或版本历史记录文档的修订历史。  

## 输出格式（LaTeX 规范）  

- 章节标题统一：确保所有章节标题格式一致，例如 `\section{}` 和 `\subsection{}`。  
- 代码块格式：软著正文使用 `lstlisting` 环境展示代码块，要求使用`style=blockstyle`，如：  
  ```latex
  \begin{lstlisting}[language=bash,style=blockstyle]
  conda create -n download python==3.9
  \end{lstlisting}
  ```  
- 行内代码也要用，如 `\lstinline|PATH|`。  
- 有些代码直接编译不了，如 `_`，还有 `\`，这些都要加上 `\lstinline`。  
- 已经在 `\begin{lstlisting}` 里面的就不用 `\lstinline|` 了。  
- `\lstinline` 内部也不需要给 `_` 加 `\` 了，例如 `get_data`、`max_results` 这种也要用 `\lstinline`，比如：  
  > 为了能够自动生成包含中文的图表，您可能需要为 Matplotlib 包添加合适的中文字体。默认情况下，使用的中文字体是 Microsoft YaHei，但如果您没有安装该字体，或者希望使用其他字体（需更改 `\lstinline|self_assembly/styles.py|`），可以按照以下步骤操作。  
- 希望保持代码块的顶格和缩进规范，使用四个空格代替制表符。  
- 需要确保所有代码块都符合这一格式要求。  
- 确保 `language=` 参数正确，避免误用语言类型。
- 化学式（结构通式、离子、电荷等）统一用 `\ce{}`（mhchem 包，已在 settings.tex 加载），不要写成代码体 `\lstinline`；例如侧链通式 `\ce{C(=O)X-(CH2)2-N+(R)(R)-(CH2)m-Y}`、季铵氮 `\ce{N+}`、氧阴离子 `\ce{O-}`。SMILES 字符串（如 `C[N+](C)(C)CC(=O)[O-]`）是机器可读输入，仍用 `\lstinline` 保留原样，不改用 `\ce{}`。

## 段落排版  
- 所有段落不要缩进，直接顶格对齐。  
- 代码也是不要用各种奇怪的手动换行，`\\` 什么的，就正常地用空格控制就行。  
- 一般不要用 `\newline`。  
- 所有表格都用三线表居中。  

## 自动检查  
在生成文档时，确保以下内容符合规范：  
- 所有章节标题是否正确分层。  
- 代码块的语言类型是否匹配实际代码。  
- 图表是否有对应的标签和引用。
- 化学式是否误用 `\lstinline`：结构通式、离子符号（季铵氮、氧阴离子等）须用 `\ce{}`，仅 SMILES 等机器可读串用 `\lstinline`。  
- 请按照上述要求，以规范化、条理化的形式输出整篇软件著作权说明文档，并确保内容符合 LaTeX 格式规范。

## 登记合规要点（一般性指导原则）

依据《计算机软件保护条例》《计算机软件著作权登记办法》及登记实务整理，适用于本仓库全部软著文档与源程序材料的编写、节选与核对。

材料一致性
- 软件名称、版本号、著作权人信息在申请表、源代码（含页眉与截图）和说明书中必须完全一致；重点核对截图中出现的软件名称与全称。
- 申请表、源代码、说明书三者描述的功能范围应相互印证，避免矛盾表述。

真实、不虚构
- 源代码须取自实际开发的软件，节选应能合理体现主要功能，不得用无关代码凑页数。
- 说明书功能必须真实存在，示例命令、截图与输出须能对应实际软件。
- 源代码与说明书均无"必须 3000 行 / 30 页"的法定下限；总量不足 60 页时提交全部，不虚构内容凑篇幅。

篇幅与排版
- 源程序：前 30 页 + 后 30 页（合计 60 页），每页不少于 50 行；不足 60 页全交。建议 A4、页眉注明软件全称、版本号与页码。
- 软件文档：前 30 页 + 后 30 页，每页不少于 30 行；不足 60 页全交。建议 A4、页眉含全称、版本号与页码。
- 上述为原则性规定，以登记平台最新审核指引为准；本仓库 `extract_front_back_pages.py` 默认取前 30 + 后 30 页并去重。

第三方与权属
- 使用第三方开源代码须注意其许可证与著作权归属，不得作为本软件独立开发成果申报；在文档"主要第三方依赖的许可证"中如实列示。
- 不愿公开的核心源程序可依法申请例外交存，并遵守材料封存规定。

文档类型选择
- 登记允许提交用户手册、操作手册或设计说明书之一，按软件类型选择：图形界面软件优先用户手册；命令行工具用使用说明书；算法/计算引擎用设计说明书；Web/综合系统用用户手册或设计说明书。
- 本仓库当前为面向用户的说明文档，以"怎么用"为主；源码未提供的功能可不写，已写信息尽量准确。

参考法规（官方）
- 国家版权局《计算机软件著作权登记办法》：登记材料、源代码页数与文档行数的主要依据。
- 《计算机软件保护条例》：著作权保护范围、权利归属与保护期限。
- 中国版权保护中心官网（www.ccopyright.com.cn）：在线申报入口与最新审核指引（登记自 2023-06-01 起全程网办、行政事业性收费已停征、受理后 60 日内审查、补正须 30 日内完成）。

## 真实源码与文档一致性核对

撰写每个软著包的说明文档前，先核对真实源码（开发目录下的实际代码）与文档描述的 API、参数、模块路径、文件名是否一致。具体流程：

1. 从开发目录抓取真实源码签名与文件、脚本路径。
2. 逐章修正说明文档中 API、参数、模块路径的不一致。
3. 核对并修正 `source-code.tex` / `code_simplified.tex` 与真实源码范围。
4. 删除冗余正文或重复示例，编译验证页数。

核对基线应记录在各软著包自己的文档目录下，不要混入本 toolkit 的通用提示。
